# GreenLLM 🌱

**تطوير: Ashraf Al tarawneh**

أداة لخفض الطاقة والبصمة الكربونية لاستخدام النماذج اللغوية (Claude وOpenAI)، من خلال تقليل ما يُحسب فعلاً: عدد الاستدعاءات وعدد الرموز، مع قياس التوفير.

يتكون المشروع من جزأين:

| الجزء | ماذا يفعل | أين يعمل |
|---|---|---|
| **البوابة `greenllm`** (Python) | خادم وسيط بين تطبيقك والمزوّد: ذاكرة مؤقتة للإجابات، Prompt Caching تلقائي، سقف لطول المخرجات، وقياس الاستهلاك | أي تطبيق يستخدم Anthropic أو OpenAI API، بما فيها Claude Code |
| **إضافة `green-ai`** لـ Claude Code | Skill لأسلوب عمل يوفّر الرموز، وHook يعرض تقديراً لطاقة الجلسة وكربونها | Claude Code |

## 1. البوابة

### التثبيت والتشغيل
```bash
pip install -e .
```
```bash
greenllm serve --port 8787
```
لوحة المتابعة: `http://localhost:8787/`، والبيانات بصيغة JSON على `/stats`، أو من الطرفية عبر `greenllm report`.

### توجيه تطبيقاتك إلى البوابة
مفاتيح API تمر كما هي إلى المزوّد ولا تُخزَّن.

**Claude Code أو Anthropic SDK:**
```bash
export ANTHROPIC_BASE_URL=http://localhost:8787/anthropic
```
**OpenAI SDK:**
```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8787/openai/v1")
```

### ما الذي توفّره فعلاً
1. **ذاكرة مؤقتة للإجابات**: الطلب المطابق تماماً يُجاب محلياً دون أي حوسبة عند المزوّد. افتراضياً يُخزَّن فقط ما كان `temperature: 0`، لأن الإجابات العشوائية لا يصح تكرارها. يمكن فرض التخزين لطلب معين بالترويسة `x-greenllm-cache: on` أو منعه بـ `off`.
2. **Prompt Caching تلقائي لـ Claude**: إذا كان الـ system prompt أو الأدوات طويلة ولم يحدد المستخدم `cache_control`، تضيفه البوابة، فيقرأ المزوّد البادئة المتكررة من ذاكرته بدل إعادة حسابها. في OpenAI يحدث هذا تلقائياً عند المزوّد، والبوابة تقيسه.
3. **سقف المخرجات** (`GREENLLM_MAX_OUTPUT_CAP`): يمنع الإجابات الطويلة بلا داعٍ.
4. **توجيه النماذج** (`GREENLLM_ROUTING`): الطلبات البسيطة تُرسل إلى نموذج أصغر، وهو غالباً أكبر مصدر للتوفير. التفاصيل في القسم التالي.
5. **ذاكرة الأسئلة المتشابهة** (`GREENLLM_SIMILAR_CACHE`): تعيد استخدام إجابة سؤال شبه مطابق. التفاصيل في القسم التالي.
6. **القياس**: يُسجَّل كل طلب (النموذج والرموز وإصابات الذاكرة المؤقتة)، ثم يُقارن بخط أساس يفترض غياب أي ذاكرة مؤقتة.

### توجيه النماذج
ثلاثة أوضاع: `off` (الافتراضي)، و`shadow` (يقيس ما كان سيُوجَّه ويعرض التوفير المحتمل دون تغيير أي طلب)، و`on`.
**ابدأ بـ `shadow`** لترى النسبة على طلباتك الفعلية قبل التفعيل.

- المصنِّف قواعد واضحة لا صندوق أسود، وكل قرار يُعاد في الترويسة `x-greenllm-route-reason`.
- يرفع درجة الصعوبة: كلمات المهام المعقدة (تصميم، تحليل، برهان، أمان، لماذا...) بالعربية والإنجليزية، والنصوص الطويلة، والكود، وطلب مخرجات طويلة. ويخفضها: الترجمة والتلخيص والتصنيف والاستخراج والتصحيح.
- **لا يوجِّه أبداً** الطلبات التي تستخدم أدوات (tools)، أو أوضاع التفكير (thinking/reasoning)، أو الصور والملفات، أو المحادثات والسياقات الطويلة. لهذا لا تتأثر جلسات Claude Code الوكيلية.
- **التصعيد**: إذا فشل النموذج الصغير أو أعاد إجابة فارغة، يُعاد الطلب تلقائياً للنموذج الأصلي، وتُحسب طاقة المحاولة الفاشلة ضمن الاستهلاك لا التوفير. الطلبات المتدفقة (stream) لا يمكن تصعيدها.
- لإيقاف التوجيه لطلب معين: الترويسة `x-greenllm-route: off`.
- الرد يحمل اسم النموذج الذي أجاب فعلاً، والترويسة `x-greenllm-routed` توضح التحويل.

### ذاكرة الأسئلة المتشابهة
تعيد الإجابة عندما يكون كل شيء متطابقاً (النموذج والتعليمات والرسائل السابقة والإعدادات) والسؤال الأخير شبه مطابق، مثل اختلاف الحروف الكبيرة أو الترقيم أو التشكيل أو كلمة إضافية. تخضع لشروط الذاكرة المؤقتة نفسها (`temperature: 0` افتراضياً).
- **حمايات**: يجب أن تتطابق الأرقام وكلمات النفي (لا، ليس، لم، بدون، not، without...) تماماً، فلا يُعاد جواب «2+3» لسؤال «2+4».
- **حدودها**: تعتمد على تشابه الحروف والكلمات، فتلتقط إعادة الصياغة السطحية لا المعنى العميق. مطفأة افتراضياً، والعتبة قابلة للضبط (`GREENLLM_SIMILAR_THRESHOLD`، والافتراضي 0.9).

### الإعدادات (متغيرات البيئة)
| المتغير | الافتراضي | الوصف |
|---|---|---|
| `GREENLLM_CACHE_MODE` | `deterministic` | `off` أو `deterministic` أو `all` |
| `GREENLLM_CACHE_TTL` | `604800` | مدة صلاحية الذاكرة المؤقتة بالثواني |
| `GREENLLM_AUTO_PROMPT_CACHE` | `true` | إضافة `cache_control` تلقائياً لـ Claude |
| `GREENLLM_AUTO_PROMPT_CACHE_MIN_CHARS` | `4000` | الحد الأدنى لطول البادئة قبل تفعيله |
| `GREENLLM_MAX_OUTPUT_CAP` | `0` (معطّل) | سقف رموز الإخراج |
| `GREENLLM_GRID_GCO2_PER_KWH` | `450` | كثافة الكربون في شبكة الكهرباء لديك |
| `GREENLLM_ROUTING` | `off` | `off` أو `shadow` أو `on` |
| `GREENLLM_ROUTE_ANTHROPIC_MODEL` | `claude-haiku-5-5` | النموذج الصغير لـ Claude |
| `GREENLLM_ROUTE_OPENAI_MODEL` | `gpt-4o-mini` | النموذج الصغير لـ OpenAI (عدّله لأحدث نموذج صغير متاح لحسابك) |
| `GREENLLM_ROUTE_MAX_SCORE` | `0` | أعلى درجة صعوبة يُسمح بتوجيهها (أعلى = توجيه أكثر) |
| `GREENLLM_SIMILAR_CACHE` | `false` | تفعيل ذاكرة الأسئلة المتشابهة |
| `GREENLLM_SIMILAR_THRESHOLD` | `0.9` | حد التشابه (0–1) |
| `GREENLLM_DB` | `greenllm.db` | ملف قاعدة البيانات |
| `GREENLLM_ANTHROPIC_BASE` / `GREENLLM_OPENAI_BASE` | العناوين الرسمية | عنوان المزوّد |

## 2. إضافة Claude Code
```bash
claude plugin marketplace add /path/to/greenllm
```
```bash
claude plugin install green-ai@greenllm
```
- **Skill `green-ai`**: يوجّه Claude إلى القراءة الموجّهة، وتجميع الاستدعاءات، والإجابات المختصرة، واقتراح نموذج أصغر للمهام البسيطة.
- **Hook**: بعد كل رد يعرض سطراً بعدد الرموز وتقدير الطاقة والكربون. لإيقافه: `GREEN_AI_QUIET=1`.

## عن دقة الأرقام (مهم)
المزوّدون لا ينشرون استهلاك الطاقة لكل رمز، لذلك فإن قيم Wh وCO₂e **تقديرات مبنية على افتراضات**، وتُعرض دائماً كنطاق (أدنى–أعلى). المعاملات موجودة في `greenllm/energy.py` ويمكن تعديلها.
أما **نسبة التوفير** فهي الأكثر موثوقية، لأنها مقارنة نسبية بالمعاملات نفسها بين الاستخدام الفعلي وخط الأساس. وأعداد الرموز نفسها حقيقية، لأنها مأخوذة من ردود المزوّد.
للنماذج المستضافة ذاتياً، القياس الحقيقي يكون بقراءة طاقة الـ GPU مباشرة (NVML أو CodeCarbon)، وهذا مخطط للمراحل القادمة.

## المراحل القادمة
- تقييم جودة التوجيه على مجموعة أسئلة حقيقية (مقارنة إجابات النموذجين).
- تضمينات دلالية حقيقية (embeddings) لالتقاط إعادة الصياغة العميقة.
- ضغط السياق في المحادثات الطويلة.
- جدولة المهام غير العاجلة حسب نظافة الكهرباء (Electricity Maps / WattTime) وBatch API.
- قياس فعلي لطاقة الـ GPU للنماذج المستضافة ذاتياً.
